## What This Notebook Does

Iterative MILP-NLP algorithm for asteroid mining route optimization:
1. **MILP** (Gurobi): selects optimal spacecraft routes given fixed mass ratios (delta-v costs)
2. **NLP** (scipy trust-constr): refines trajectory timing (T_d, T_t) per segment via Lambert's problem, updating mass ratios
3. Repeats until delta-v matrix converges per Eq. 47: `||dv_old - dv_new||_F / max(dv_old) ≤ ε_c`

## Complete List of All Bugs Fixed (across both sessions)

### Bug 1 — Mass constraints had cargo term y[k,i] on wrong legs (CRITICAL)
**Cell 18** | Paper Eqs. 41–42  
Ending-base legs must carry the cargo term `m_dry + y[k,i] ≤ m_ij*(u[i]+m_m) + M*(1-x)`.  
Before: cargo term was on intermediate legs, not ending-base legs. Fixed.

### Bug 2 — y[k,i] linearization activated on any outgoing arc, not just ending-base arc (SIGNIFICANT)
**Cell 18** | Paper: y_ki = q_i * x^k_{i,k'(k)}  
Before: y[k,i] could activate for any arc leaving i. After: only for the ending-base arc x[k,i,k'(k)]. Fixed.

### Bug 3 — NLP used L-BFGS-B with artificial 3 TU cap on departure time (SIGNIFICANT)
**Cell 14** | Paper Sec. IV.B.2: only lower bound T_d ≥ T_a + T_s  
Before: `L-BFGS-B`, bounds `[T_d_min, T_d_min+3]` — blocked favorable late windows.  
After: `trust-constr`, bounds `[T_d_min, ∞]`. Fixed.

### Bug 4 — Convergence denominator was Frobenius norm, not max element (MODERATE)
**Cell 24** | Paper Eq. 47: divide by `max(dv_old)` (scalar), not `||dv_old||_F`  
Fixed to use `max(old_dv_matrix.values())` as denominator.

### Bug 5 — Hard constraint forced 1 spacecraft regardless of problem (MODELING)
**Cell 18** | Paper allows multiple vehicles  
Removed artificial `sum(x) ≤ 1` constraint.

### Bug 6 — trust-constr res.success=False blocked valid NLP solutions (SIGNIFICANT)
**Cell 14** | scipy known behaviour: trust-constr returns success=False when gradient tolerance not met, even with good function value  
Removed `res.success` from the success check. Now only checks `res.fun < 100.0`.

### Bug 7 — Same-body arcs given mr=0.999 in initialization (CRITICAL)
**Cell 21** | initialize_mass_ratios  
Before: `if body_i.name == body_j.name: mass_ratios[(i,j)] = 0.999`. This made virtual-node hops like Bennu→Bennu appear nearly free, corrupting MILP route choices from iteration 1.  
After: same-body pairs simply skipped — not added to mass_ratios at all.

### Bug 8 — Same-body arcs created as MILP variables (CRITICAL)
**Cell 18** | build_milp V→V arc creation  
Before: `if i != j:` created arc variables for Bennu(node 9)→Bennu(node 11), etc.  
After: `if i != j and node_to_body[i].name != node_to_body[j].name:` — same physical body arcs never created. Also passes `node_to_body` as parameter.

### Bug 9 — Convergence check used full dv matrix including stale off-route arcs (MODERATE)
**Cell 24** | Off-route arcs from previous iterations inject noise into Frobenius norm  
After: convergence check restricted to `current_arc_set` (arcs in the active route only).

### NLP Oscillation Fixes (not bugs per se, but algorithm stability)
**Cells 14 and 24** | trust-constr finds slightly different local minima each call  
Four fixes applied together:
1. **T_d warm-start**: `optimize_segment` now takes `T_d_prev`, starts from `max(T_d_prev, T_d_min)`
2. **Tighter tolerances**: `gtol=1e-8, xtol=1e-8, maxiter=500` — solver commits to precise local min
3. **Active-arc convergence**: check only current route arcs (see Bug 9)
4. **Arc freezing**: arcs appearing in 2+ consecutive identical routes skip NLP re-run; cached result reused. Eliminates residual oscillation on stable routes.
