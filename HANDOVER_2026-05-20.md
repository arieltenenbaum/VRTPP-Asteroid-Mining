## What Was Done This Session

### 1. Experiment Infrastructure Overhaul

The goal was to make experiments faster and to document the MILP optimality gap so that the paper model and our model can be compared fairly.

**Key design decision:** both models now use identical Gurobi settings (`MIPGap=0.0`, `TimeLimit=30s`) so results are directly comparable. The previous `our_model` setting of `MIPGap=0.03` was changed to match the paper model's exact setting.

### 2. `VRTPP-PaperModel.ipynb` — Cell 26 (`solve_vrtpp_pr`)

**File:** `VRTPP-PaperModel.ipynb`, Cell 26

Three changes:

1. **Added `time_limit` parameter** to function signature:
   ```python
   # Before
   def solve_vrtpp_pr(params, sets, node_to_body, node_to_name,
                      max_iterations=50, convergence_tol=1e-3):
   # After
   def solve_vrtpp_pr(params, sets, node_to_body, node_to_name,
                      max_iterations=50, convergence_tol=1e-3,
                      time_limit: float = 100.0):
   ```
   Default stays 100.0 — interactive notebook use is unchanged.

2. **`TimeLimit` now uses the parameter** (was hardcoded):
   ```python
   model.setParam('TimeLimit', time_limit)  # was 100.0
   ```

3. **MIPGap tracking added:** after each `model.optimize()`, `model.MIPGap` is appended to a `mip_gaps` list. At the end of the solve, `mip_gap_final` (last MILP call's gap) and `mip_gap_mean` (average across all iterations) are returned in the solution dict.

### 7. Context: Why These Settings

| Setting | Value | Reason |
|---------|-------|--------|
| `MIPGap` | 0.0 | Paper uses exact optimality; our model now matches for fair comparison |
| `TimeLimit` | 30 s | Caps MILP per call; paper used 100 s but 30 s is sufficient for small configs and avoids multi-hour runs on large ones |
| `N_INSTANCES` | 5 | Down from 10; statistically meaningful and halves runtime |
| Configs | n_r=1,2 × n_m=4,6,8 | Matches paper's scale; skips n_m=10 and n_r=3 as too slow without dedicated compute |
