## What This Notebook Does
Implements the iterative MILP-NLP algorithm from the VRTPP-PR paper for asteroid mining route optimization. The loop alternates between:
1. **MILP** — selects optimal spacecraft routes given fixed mass ratios (delta-v costs)
2. **NLP** — refines trajectory timing for the chosen routes, updating mass ratios
3. Repeats until routes and delta-v matrix converge (Eq. 47 Frobenius norm criterion)

## Changes Made

### Bug 1 — Mass constraints had intermediate/ending-base cargo terms swapped (CRITICAL)
**Cell:** 18, `build_milp()`  
**Paper reference:** Eqs. 41–42 (ending-base mass constraints with cargo term y_ki)

**Before:**
- Intermediate legs (M/R → V): added `m_dry + y[k,i] <= m_ij * (u[i] + m_m) + ...`  ← wrong
- Ending-base legs (M/R → k'): added `m_dry <= m_ik * (u[i] + m_m) + ...`  ← wrong

**After:**
- Intermediate legs: only `u[j] <= m_ij * (u[i] + m_m) + ...` (already correct in earlier block, duplicate blocks removed)
- Ending-base legs: `m_dry + y[k,i] <= m_ik * (u[i] + m_m) + M*(1 - x[k,i,k'(k)])` ← now correct

**Why it mattered:** The mined cargo term y[k,i] was never enforced on the return leg to base, while it was over-constraining intermediate hops. This could cause artificial infeasibility or bad route choices.

---

### Bug 2 — y[k,i] linearization was too broad (SIGNIFICANT)
**Cell:** 18, `build_milp()` linearization block  
**Paper reference:** y_ki = q_i * x^k_{i,k'(k)} (specifically the ending-base arc only)

**Before:** y[k,i] activated whenever ANY outgoing arc from i was active for spacecraft k.

**After:**
```python
model.addConstr(y[k, i] <= q[i])
model.addConstr(y[k, i] <= q_max * x[k, i, k_prime[k]])
model.addConstr(y[k, i] >= q[i] - q_max * (1 - x[k, i, k_prime[k]]))
```
y[k,i] = q[i] only when spacecraft k takes the ending-base arc from i.

### Bug 3 — optimize_segment used L-BFGS-B with artificial T_d upper cap (SIGNIFICANT)
**Cell:** 14, `TrajectoryOptimizer.optimize_segment()`  
**Paper reference:** Sec. IV.B.2 — trust-region NLP, only lower bound T_d >= T_a + T_s

**Before:**
- Method: `L-BFGS-B` 
- Bounds: `[(T_d_min, T_d_min + 3), (0.5, 15)]` — hard cap 3 TU on departure window
- Signature: `optimize_segment(self, body_i, body_j, T_arrival_i)`

**After:**
- Method: `trust-constr`
- Bounds: `[T_d_min, 1e-5]` to `[inf, 30.0]` — only lower bound on T_d (paper's formulation)
- Signature: `optimize_segment(self, body_i, body_j, T_arrival_i, T_t_prev=None)`
- Initial guess: uses `T_t_prev` from prior iteration if available, otherwise Hohmann

**Why it mattered:** The `T_d_min + 3` cap prevented the solver from finding favorable transfer windows that require waiting. The paper explicitly only constrains T_d from below.

### Bug 4 — Convergence check only used route arcs, not full matrix (MODERATE)
**Cell:** 24, `solve_vrtpp_pr()` convergence block  
**Paper reference:** Eq. 47 — `||Δv_old - Δv_new||_F / max(Δv_old) ≤ ε_c`

**Before:** Compared only arcs present in the current optimized route.

**After (initial fix):** Used union of all arcs with Frobenius norm of old matrix as denominator — still wrong.

**After (corrected in same session):** Now matches Eq. 47 exactly — denominator is `max(Δv_old)` (the maximum single element, a scalar), not the Frobenius norm:
```python
all_keys = set(old_dv_matrix.keys()) | set(delta_v_matrix.keys())
change = sqrt(sum((dv_new - dv_old)^2)) / max(dv_old.values())
```

### Bug 5 — Hard constraint limiting MILP to 1 spacecraft (MODELING CHOICE)
**Cell:** 18, `build_milp()`

**Before:**
```python
model.addConstr(gp.quicksum(...) <= 1)  # Limit to 1 spacecraft
```

**After:** Removed. The paper's formulation allows multiple vehicles; the case-study optimal happened to use one. This constraint was artificially restricting the search space.
